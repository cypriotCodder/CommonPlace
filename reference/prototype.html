Databases · Concept 01

Understanding indexes

A way to find the rows you need without searching through every row you have.

◷  8 min read○  Foundations◎  Read, practice, review

The idea

Imagine looking for a name in a book with no index. You might have to turn every page. A database faces a similar problem when it searches a table: without a useful index, it may need to examine many rows.

An index is a separate data structure that helps the database locate rows by the values in one or more columns. It gives the query planner another route to the data, but it does not guarantee that the planner will take it.

Think of it this way. An index is a shortcut to possible locations, not a copy of the whole table and not a promise that every query will be faster.

How it helps

Suppose an application often looks up orders for one customer. An index on customer_id can help find matching entries without scanning the entire orders table.

SELECT * FROM orders
WHERE customer_id = 42;

Common B-tree indexes keep values in an ordered structure. That can help with equality and range conditions, depending on the query and the data. If a query needs most of the table anyway, a scan may be cheaper.

The tradeoff

Indexes take space, and the database must maintain them as rows are inserted, updated, or deleted. More indexes can make reads faster while adding work to writes. Choose them for queries that matter, then measure the result with the database’s query plan.
